# Coordinator: параллельные in-progress задачи

Author: **Evgeny KOSIVTSOV** (`EK`)
Created: 2026-09-09 14:23
Branch: `main`
Services: Common, `.cursor`, `.coordinator`

Несколько задач `in_progress` у одного человека, если не пересекаются product-сервисы и смысл. Ресёрч всегда параллелен. Пульс: отдельная карточка на задачу и на ресёрч.

## Зачем

Один слот на алиас заставлял гасить ARC, чтобы поправить дашборд. Ресёрч уже жил рядом с задачей; задачи друг с другом — нет. `task_started` перезаписывал снимок, и предыдущая строка в Tasks навсегда оставалась In progress.

Диск воркспейса — набор независимых git-репозиториев. Конфликт — один `HEAD` в одном репо, не «две вкладки на весь воркспейс».

## Модель

`.current_task_<ALIAS>` — по-прежнему один файл на человека (без merge-конфликтов между людьми). Поле `tasks[]` — открытые слоты. Корень `task_id` / `branch` / `services` зеркалит **последний** стартовавший слот (совместимость).

Ресёрч — по-прежнему вложенное `research`. `task_started` его **не** закрывает. Закрытие: эта вкладка, `sessionEnd`, 30 минут тишины, явный `research_completed`. Переход «этот чат из ресёрча в задачу» — `research_completed` этой сессии, затем `task_started`; чужой ресёрч не трогать.

`Common` — шина координации, не скоуп задачи. Не блокирует параллель.

`.cursor` / `.coordinator` — для **команды** не коллизия; у **того же алиаса** два слота с одним из этих репо нельзя (один working tree).

Чужой **product**-репо при разных ветках — не стоп: предупредить и писать `coordinator_warning`. Свой тот же product-репо — стоп. Подробно: [peer scope](./20260912-1121-EK-COORDINATOR_PEER_SCOPE.md).

## Мозг

Правило `.cursor/rules/coordinator/parallel.mdc`. Перед `task_started` — только оно решает, можно ли добавить слот. Workflow мержа остаётся в `coordinator/protocol.mdc`.

## Пульс и Tasks

Одна карточка = одна задача **или** ресёрч. Не два бейджа на ARC.

**In progress в Tasks** — те же слоты, что в Пульсе (`tasks[]` снимка). `task_started` без `task_completed`, которого уже нет в снимке (перезаписанный одиночный слот), не остаётся «в работе» навсегда: строка закрывается на старте следующей задачи того же алиаса.

## Финансы

Карточки Share of plan / On-demand суммируют расход **за текущий биллинг-цикл Cursor** (`billing_cycle_start` из live snapshot), не за календарный день. Сегодня — отдельной строкой.

## Локальный просмотр

UI — Vite `:5175` (`./utils/frontend.sh start` / `npm run dev`). API — detached Go `:4321` (`./utils/backend.sh`). После правок бека — `./utils/backend.sh restart`; фронт сам подхватывает HMR.

## Критерий готовности

Пока ARC (`Core`) открыт, стартует задача координатора на `main`. Снимок хранит оба слота. Tasks показывает оба In progress. Пульс — две карточки задач, ресёрч отдельно если активен.
