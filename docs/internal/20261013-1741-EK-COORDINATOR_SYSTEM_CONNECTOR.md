## Две плоскости

Это разные продукты с общей шиной, не «коннектор внутри Pulse».

Две связи, их нельзя смешивать:

| Плоскость | Направление | Зачем |
|-----------|-------------|--------|
| **Данные** | Remote → git-шина → Координатор | Durable: ExternalEvent / ExternalKnowledge. Jira Координатор не трогает |
| **Управление** | Координатор (настройки) ↔ Remote API | Подключить сотрудника, токен, права; админ — коннекторы. Не ingest |

```text
  Jira / Confluence / CI / …
           ▲
           │  данные: ходит только Remote
           │
  ┌────────┴────────┐         git-шина (coordinator-state)
  │  .coordinator/  │  ──пишет──►  progress/external/…
  │     remote      │
  │  (коннекторы,   │
  │   выдача токенов)
  └────────┬────────┘
           │
           │  управление: HTTP из настроек Координатора
           │  (адрес + локальный access token)
           ▼
  ┌─────────────────┐         читает шину; Pulse / Отто / UsePolicy
  │  .coordinator/  │
  │ backend+frontend│
  └─────────────────┘
```

| Плоскость | Где живёт | Делает | Не делает |
|-----------|-----------|--------|-----------|
| **Координатор** | `.coordinator/backend`, `frontend` | Потребляет знания и события; смысловая реакция (UsePolicy); **пара** с Remote из настроек | Не ходит в Jira, не хранит токены Jira, не знает адаптеров |
| **Remote** | `.coordinator/remote` | Ходит во внешние системы; свои коннекторы; пишет в шину; **выдаёт** токены сотрудникам | Не открывает слоты, не overlap, не голос Отто |

## Как назвать Remote

Каталог: **`.coordinator/remote`** — рядом с `backend/` и `frontend/`, отдельный процесс (как API на `:4321`, только свой бинарь и порт).

В речи и `go.mod` пакета — **Remote**, не «cloud sync» и не «remote sync»:

| Имя | Почему нет / да |
|-----|-----------------|
| cloud sync | Врёт: первый runtime — инфра **клиента**, не наш cloud |
| remote sync | «Sync» звучит как двусторонняя зеркальная синхронизация с Jira |
| ingest / harvester | Точно по роли, но плохо как имя продукта |
| **Remote** | Совпадает с путём; «удалённый контур». Достаточно, пока нет второго имени |
| Relay | Запасное, если «Remote» окажется слишком пустым: односторонняя ретрансляция в шину |

Коннекторы (Jira, Confluence) — **домен Remote**, имена вида `JiraConnector` внутри `.coordinator/remote`. На стороне Координатора слова Connector для внешних систем **нет**: там уже есть CrewConnector, и смешивать нельзя.

Старое рабочее **SystemConnector** снимаем. Это был конфиг подписки, замаскированный под сущность Pulse.

## Что видит Координатор

Два типа записей (плюс позже UsePolicy). Источник правды по-прежнему шина; с **парой** Координатор ещё может **подтянуть** свежее с Remote API (read). Без пары оверлей по умолчанию скрыт.

### ExternalEvent

Дискретное «случилось»: QA failed, тикет сдвинулся, сборка красная.

Не строка в `events/EK/2026.jsonl` (`model.Event` = действия человека). Соседний журнал, оверлей Pulse как conflicts/stray:

```text
Pulse: members[] + conflicts[] + stray[] + external.events[] + external.knowledge[]
```

Черновик полей:

| Поле | Смысл |
|------|--------|
| `id` | Id в нашей шине |
| `source` | Откуда (`jira`, …) — метка, не объект коннектора |
| `origin_id` | Id коннектора **в Remote** (для трассировки; Координатор его не вызывает) |
| `external_id` | Id во внешней системе |
| `occurred_at` | Время там |
| `kind` | Класс (`qa.failed`, …) |
| `title` / `summary` | Для Pulse и Отто |
| `crew_id` | Если Remote замапил |
| `task_id` / `alias` | Опционально |
| `url` | Ссылка наружу |

### ExternalKnowledge

Снимок, не лог: страница Confluence, выжимка epic. Markdown/текст + `updated_at` + `external_id`. Не зеркало wiki.

### UsePolicy

Смысл **на стороне Координатора**: когда Отто смотрит на эти записи. Remote про политику не знает.

Примеры якорей: `before_task_started`, `notify`, `brief_on_view`. Первая версия — текст, как `interest_brief`. Жёсткий stop из Jira в overlap — не v1.

## Что такое коннектор (только Remote)

В Remote — развитый домен: источник, учётные данные (env), фильтры, маппинг на `crew_id`, нормализация в ExternalEvent / ExternalKnowledge.

Конфиг подписок живёт **у Remote** (его settings / env), не в `org_topology.json` Координатора. Crews-файл **`system_connectors` не получает**.

Витрина коннекторов для **чтения** может дублироваться в шину. Живое **администрирование** (добавить/выключить коннектор) — только Remote API по admin-токену, UI в настройках Координатора.

Секреты Jira/Confluence — только env Remote на сервере. Access token сотрудника — только на его машине, см. ниже.

## Хранилище (шина)

Пишет **Remote**. Читает **Координатор** (SQLite-кэш как у jsonl людей).

```text
Common/data/progress/external/
  events/<origin_id>/<YYYY>.jsonl
  knowledge/<origin_id>/<external_id>.md
```

Ветка `origin/coordinator-state`, не `Common` `main`. Не класть сырой JSON Jira целиком.

Идемпотентность: `source` + `external_id`.

## Управление Remote из настроек Координатора

Remote сначала поднимают в инфре клиента (отдельный шаг установки). Потом **участник** в Координаторе подключает доступ — не наоборот: без живого Remote парить нечего.

Это не `access: admin|member` из `team.json` (это права дашборда Координатора). Права на Remote живёт на **токене, который выдал Remote**.

### Когда в установке

После того как Remote отвечает на health (URL известен команде). В сетапе или в настройках — блок **«Remote»**.

### Пара

1. Человек вводит **адрес** сервиса (`https://remote.example.internal`).
2. Координатор стучится на Remote: доступен ли, готов ли выдать сессию (health + handshake).
3. Remote **проверяет**, можно ли этому человеку токен (инвайт установщика, первый admin, позже — org/GitHub — открыто).
4. Remote отдаёт **access token**. Координатор кладёт его **локально** (gitignore), рядом по духу с `.current_author` — например `Common/data/.remote_access`. В git, в `team.json` и в шину токен **не** пишется.
5. URL Remote на этой машине — в том же локальном файле (или URL общий в `coordinator.json`, токен всё равно локальный).

Повторный заход: есть локальный токен → проверка, что Remote его ещё принимает. Отозвать — на стороне Remote; локально стереть файл.

### Два уровня токена

| Scope | Что может сотрудник из Координатора |
|-------|--------------------------------------|
| **read** (потребитель) | Получать события и обновления знаний: оверлей Pulse, pull/refresh с Remote, если шина отстала. Коннекторы не трогает |
| **admin** | Всё из read **плюс** администрировать Remote: подключать и выключать коннекторы, фильтры, маппинг на crew. UI — вкладка настроек, запросы идут в Remote API |

Один человек — один токен со списком scope. Сменить read→admin = перевыпустить на Remote, не флажок в `team.json`.

Координатор **не** ходит в Jira даже у admin: форма «новый коннектор» сохраняется **на Remote**; секреты внешней системы вводит admin в том же UI, уходят в Remote, на диск сотрудника не кладутся (кроме access token).

### Что без пары

Без локального токена Координатор остаётся как сейчас: слоты, git людей. Оверлей `external.*` не показываем (или только то, что уже в шине, если команда так решит — по умолчанию **нужна пара**, иначе чужой клон без допуска не видит внешнее).

### Не путать с шиной

Пара не заменяет запись в `coordinator-state`. Remote по-прежнему **пишет** события в git. Токен — кто с этой машины имеет право **забирать** обновления и **менять** Remote. Ноутбук не становится ingest-воркером.

## Пример

1. Jira: тикет → Failed.
2. Remote (JiraConnector) нормализует → ExternalEvent `qa.failed`, `crew_id=core-dev`.
3. Коммит в state-шину.
4. Координатор с **read**-токеном видит запись на Pulse (шина и/или refresh с Remote). UsePolicy инженерии — перед новой задачей Отто может сказать. Ingest в этом шаге без Координатора.

## Фазы

### Фаза 0 — этот документ

Согласовать плоскости и имена.

### Фаза 1 — контракт шины

Каталог `progress/external/`, Координатор умеет **прочитать** оверлей. Remote может быть скриптом, который кладёт одну запись — без UI Jira.

### Фаза 2 — `.coordinator/remote` и пара из настроек

Отдельный сервис, health, выдача токена. В Координаторе: адрес → handshake → локальный `.remote_access`. Scope `read` | `admin`. Первый адаптер (Jira или CI) — для admin UI. Вебхук и секреты внешних систем остаются на Remote.

### Фаза 3 — UsePolicy у Отто

Advisory, без stop overlap.

### Не входит

- Координатор ходит в Jira / Confluence сам.
- Двусторонний sync тикетов.
- Автослот из Jira.
- SystemConnector / IntegrationConnector в модели Pulse.
- CrewConnector и коннекторы Remote в одном массиве.
- Токен Remote в git или в `team.json`.

## Открытые решения

1. Имя продукта: оставить **Remote** или переименовать в **Relay** до первого кода.
2. Первый адаптер: Jira vs CI (`deploy_*` в человеческом jsonl не дублировать).
3. `kind` события: закрытый enum с первого адаптера или строка + tags.
4. Knowledge: файл в git vs url + выжимка.
5. Как Remote узнаёт, что человеку можно токен: инвайт-код установщика, первый admin, GitHub org.
6. URL Remote: только локально vs подсказка в `coordinator.json` + токен всё равно локальный.
7. Без пары: скрывать `external.*` полностью или показывать уже попавшее в шину.
